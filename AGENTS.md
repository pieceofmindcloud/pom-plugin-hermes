# Hermes plugin agent memory

- This repository is a POM `cdylib` plugin scaffolded from `creating-pom-plugins`; contract details are in the POM repository's `docs/subsystems/plugins-ui.md` and `enterprise-licensing.md`. `src/abi.rs` is the panic-safe C ABI; `src/lib.rs` dispatches requests. Never block `query` (3-second IPC timeout).
- `src/supervisor.rs` owns background children and the supervised bridge. `src/installer.rs` downloads and SHA-256 verifies the pinned Hermes tarball and platform-specific uv, extracts only regular files with confined paths, installs managed Python 3.14.9, delegates dependencies to upstream `pm.cli install`, and calls upstream `hermes_cli/source_completion.py` to build TUI/web and sync config and skills. No Python, bash, Git, curl or Node from the host is required for first install. Do not replace Hermes PM with `pip install` or system Node; its source rejects wheels. `runtime.py` only launches the managed dashboard and acts as the per-launch authenticated loopback bridge. A standalone Linux install with system Python/Git/curl/Node/npm masked and a live dashboard root and `/api/status` was verified locally. The on-demand smoke workflow completed the same full install and live dashboard test on native macOS and Windows runners; Windows also produced a release-mode `.dll`. Regular CI compiles/tests Linux, macOS and Windows.
- POM strips browser Authorization. The bridge verifies `x-pom-plugin-token` from POM *before* adding its own per-launch Hermes auth; it rewrites Host for Hermes's loopback guard and sends `X-Forwarded-Prefix` for its prefixed SPA. Do not forward browser cookies or secrets. `rpc.status` and `host.services` never include private tokens, ports, or gateway keys.
- Fixed files, source, logs and PM tools live next to `POM_PLUGIN_DB` under `hermes/`. Hermes user data is under `workspace_root/.hermes/` (fallback to runtime `data/`). Only the first setup may create a POM model config; existing Hermes settings are never overwritten. The Hermes dashboard itself handles later changes, including POM API key rotation.
- `ui/manifest.json` and `release/manifest.json` are separate. UI reads `__POM_HOST__` only in `ui/src/host/*`; the `pb-` CSS prefix is renamed to `hermes-` during the build. `scripts/dev-ui.sh` writes outside the read-only dev source mount.
- Verify with `scripts/build-ui.sh`, `POM_UI_REQUIRE_DIST=1 cargo test --locked`, `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, `python3 -m unittest discover -s tests -p 'test_runtime.py'`, and `tests/test_ci_plan.sh`. The ignored `cargo test --locked installer::tests::installs_without_system_python_git_or_curl -- --ignored --nocapture` performs a full install and tests the live authenticated dashboard; it requires network, several gigabytes and time. `.github/workflows/installer-smoke.yml` runs it on demand on Windows, macOS or Linux. Release packaging supports all three.
