# Hermes Agent

Open **Hermes Agent** in the POM sidebar. On the first visit, enter an optional POM model ID (from a model already deployed on this node's network) to make it the initial model, then select **Install and open Hermes**. The installation runs in the background and can be retried without losing settings. It downloads several gigabytes from GitHub and the upstream dependency registries. The plugin supplies a verified, managed Python and delegates further tools and dependencies to Hermes PM; no Python, Node, Git, curl, bash or special Docker image is required on the host. Linux, macOS and Windows were validated by full install and live dashboard smoke tests. Integration inside a running Windows POM node has not yet been field-tested.

The POM screen hosts the official Hermes dashboard at the POM origin, edge to edge with no POM chrome; its menus, channels, model settings and credentials are managed by Hermes. The dashboard is local to this node. An authenticated POM operator who can open this plugin can manage all of this Hermes installation, including its stored keys. Do not grant POM UI access to untrusted operators.

Deployed POM models appear in Hermes under the **POM** provider without further configuration: the plugin registers the provider through Hermes's own settings, stores the node's gateway key in Hermes's private `.env` and lists the `/v1/models` catalog. Choosing a POM model in Hermes's model picker starts the distributed POM inference. The optional first-setup model ID only sets Hermes's initial default.

The POM model connection saves `providers.pom` pointing at the node's loopback `/v1` and the gateway credential in Hermes's owner-only `.env` (`POM_API_KEY`). The initial model, when given during setup, is `model.provider: custom` with the POM endpoint. Later edits to Hermes's configuration stay under Hermes's control. A rotated POM gateway key is refreshed automatically by the plugin on Hermes restarts and must be refreshed in Hermes's Keys page only if the operator manages it by hand.

The plugin skips the upstream installer's optional browser and computer-use components. The official source-completion stage builds the TUI and web interface and syncs Hermes's bundled skills and configuration. This source archive is not a Git checkout, so upstream Git-based self-update requires a separate checkout. To enable them later, follow the upstream Hermes PM instructions. Consult the Hermes project's dashboard documentation for configuration of messaging platforms, other providers and tools.
