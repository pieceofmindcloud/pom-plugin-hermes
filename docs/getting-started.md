# Hermes Agent

Open **Hermes Agent** in the POM sidebar. On the first visit the installation starts by itself, behind POM's installer: a progress bar and a line saying what is happening (downloading Hermes, the Python runtime, installing packages, building the dashboard, connecting to POM's models). When it finishes the dashboard opens. If it fails, the error is shown with **Try again**, which retries without losing settings. Later visits open the dashboard directly. Choose the model inside the Hermes dashboard. It downloads several gigabytes from GitHub and the upstream dependency registries. The plugin supplies a verified, managed Python and delegates further tools and dependencies to Hermes PM; no Python, Node, Git, curl, bash or special Docker image is required on the host. Linux, macOS and Windows were validated by full install and live dashboard smoke tests. Integration inside a running Windows POM node has not yet been field-tested.

The POM screen hosts the official Hermes dashboard at the POM origin, edge to edge with no POM chrome; its menus, channels, model settings and credentials are managed by Hermes. The dashboard is local to this node. An authenticated POM operator who can open this plugin can manage all of this Hermes installation, including its stored keys. Do not grant POM UI access to untrusted operators.

Deployed POM models appear in Hermes under the **POM** provider without further configuration: the plugin registers the provider through Hermes's own settings, stores the node's gateway key in Hermes's private `.env` and lists the `/v1/models` catalog. Choosing a POM model in Hermes's model picker starts the distributed POM inference.

The POM model connection saves `providers.pom` pointing at the node's loopback `/v1` and the gateway credential in Hermes's owner-only `.env` (`POM_API_KEY`). Later edits to Hermes's configuration stay under Hermes's control. A rotated POM gateway key is refreshed automatically by the plugin on Hermes restarts and must be refreshed in Hermes's Keys page only if the operator manages it by hand.

The plugin skips the upstream installer's optional browser and computer-use components. The official source-completion stage builds the TUI and web interface and syncs Hermes's bundled skills and configuration. This source archive is not a Git checkout, so upstream Git-based self-update requires a separate checkout. To enable them later, follow the upstream Hermes PM instructions. Consult the Hermes project's dashboard documentation for configuration of messaging platforms, other providers and tools.
