# Hermes Agent

Open **Hermes Agent** in the POM sidebar. On the first visit, enter an optional POM model ID (from a model already deployed on this node's network), then select **Install and open Hermes**. Without a POM model, choose your provider in Hermes after the dashboard opens. The installation runs in the background and can be retried without losing settings. It downloads several gigabytes from GitHub and the upstream dependency registries. The plugin supplies a verified, managed Python and delegates further tools and dependencies to Hermes PM; no Python, Node, Git, curl, bash or special Docker image is required on the host. Linux, macOS and Windows were validated by full install and live dashboard smoke tests. Integration inside a running Windows POM node has not yet been field-tested.

The POM screen hosts the official Hermes dashboard at the POM origin; its menus, channels, model settings and credentials are managed by Hermes. The dashboard is local to this node. An authenticated POM operator who can open this plugin can manage all of this Hermes installation, including its stored keys. Do not grant POM UI access to untrusted operators.

The POM model connection saves `model.provider: custom` and the POM's loopback `/v1` endpoint in Hermes's `config.yaml`, and saves the gateway credential in its owner-only `.env`. It applies only during the first setup; later edits to Hermes's configuration stay under Hermes's control. A rotated POM gateway key must be refreshed in Hermes's Keys page.

The plugin skips the upstream installer's optional browser and computer-use components. The official source-completion stage builds the TUI and web interface and syncs Hermes's bundled skills and configuration. This source archive is not a Git checkout, so upstream Git-based self-update requires a separate checkout. To enable them later, follow the upstream Hermes PM instructions. Consult the Hermes project's dashboard documentation for configuration of messaging platforms, other providers and tools.
